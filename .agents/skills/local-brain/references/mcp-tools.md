# MCP Tools Catalog — Local Brain

Local Brain exposes 11 standard tools via the **Model Context Protocol (MCP)** over `stdio`. This catalog documents each tool, parameter types, default values, and usage patterns.

---

## 1. `brain_remember`
Stores a new memory or experience with local PostgreSQL persistence, 768-dimensional embeddings generated by local `llama.cpp` (`nomic-embed-text-v1.5`), cognitive specialization, and provenance metadata.

### Parameters
- `content` *(string, optional if structured fields are provided)*: Textual content of the memory.
- `memory_type` *(string, optional, enum: `"episodic"`, `"semantic"`, `"procedural"`, `"associative"`, `"working"`, default: `"episodic"`)*: Cognitive memory type.
- `project` *(string, optional, default: `"default"`)*: Associated project name.
- `agent` *(string, optional, default: `"mcp-agent"`)*: Agent identifier.
- `importance` *(number, optional, [0.0 - 1.0], default: 0.5)*: Intrinsic importance.
- `confidence` *(number, optional, [0.0 - 1.0], default: 0.3)*: Empirical confidence score.
- `session_id` *(string, optional)*: Active session ID for working memory.
- `ttl_seconds` *(integer, optional, >= 1)*: Time-to-live in seconds before expiration (for `working`).
- **Episodic Fields:**
  - `context` *(string)*: Situational context (what was being attempted).
  - `action` *(string)*: Decision or action taken.
  - `outcome` *(string)*: Observed empirical outcome.
- **Semantic Fields:**
  - `statement` *(string)*: Generalized principle or factual statement.
  - `evidence_ids` *(array of strings)*: UUIDs of supporting evidence (mandatory if confidence >= 0.8).
  - `domain_area` *(string)*: Knowledge domain.
- **Procedural Fields:**
  - `goal` *(string)*: Target goal of the procedure.
  - `steps` *(array)*: List of steps (strings or objects with `step_number`, `description`, `command`, `action_type`).
- **Associative Fields:**
  - `source_concept` *(string)*: Source concept entity.
  - `target_concept` *(string)*: Target concept entity.
  - `predicate` *(string)*: Relationship predicate.
  - `strength` *(number, [0.0 - 1.0], default: 0.5)*: Association weight.

### Example
```json
{
  "project": "ecommerce",
  "memory_type": "episodic",
  "context": "Query optimization on product search catalog",
  "action": "Created a pgvector HNSW index on category embeddings",
  "outcome": "Latency decreased from 230ms to 14ms in local benchmark",
  "importance": 0.85,
  "confidence": 0.90
}
```

## 2. `brain_recall`
Recalls memories via dense vector similarity search (768 dimensions), direct UUID lookup, or basic filters (project, type, session, concept).

### Parameters
- `query` *(string, optional)*: Query string for cosine vector similarity search.
- `id` *(string, optional)*: UUID of a specific memory record.
- `project` *(string, optional)*: Filter by project.
- `memory_type` *(string, optional, enum: `"episodic"`, `"semantic"`, `"procedural"`, `"associative"`, `"working"`)*: Filter by cognitive type.
- `session_id` *(string, optional)*: Filter by active session.
- `concept` *(string, optional)*: Filter conceptual associations.
- `limit` *(integer, optional, 1 to 50, default: 10)*: Maximum results.

---

## 3. `brain_search`
Multi-criteria search combining semantic queries, ISO 8601 date ranges, importance cutoffs, and session filters.

### Parameters
- `query` *(string, optional)*: Search query string.
- `project` *(string, optional)*: Filter by project.
- `memory_type` *(string, optional)*: Filter by memory type.
- `session_id` *(string, optional)*: Filter by session.
- `concept` *(string, optional)*: Filter by concept.
- `min_importance` *(number, optional, [0.0 - 1.0])*: Minimum importance threshold.
- `from_date` *(string, optional, ISO 8601)*: Start creation timestamp.
- `to_date` *(string, optional, ISO 8601)*: End creation timestamp.
- `limit` *(integer, optional, 1 to 50, default: 10)*: Maximum results.

---

## 4. `brain_retrieve`
Advanced hybrid retrieval fusing three simultaneous channels (Vector HNSW + PostgreSQL Full-Text Search + Knowledge Graph Expansion) with Reciprocal Rank Fusion (RRF), multidimensional scoring, and exponential recency decay.

### Parameters
- `query` *(string, required)*: Semantic and lexical search intention.
- `project` *(string, optional)*: Filter by project.
- `memory_type` *(string, optional)*: Filter by cognitive type.
- `limit` *(integer, optional, 1 to 100, default: 10)*: Maximum returned memories.
- `min_score` *(number, optional, [0.0 - 1.0])*: Minimum ranking cutoff score.
- `explain` *(boolean, optional, default: false)*: If `true`, returns mathematical breakdown of ranking signals.

### Example
```json
{
  "query": "how to execute zero downtime schema migrations",
  "project": "local-brain",
  "limit": 5,
  "explain": true
}
```

## 5. `brain_relate`
Creates a typed, weighted semantic edge between two memories or concepts in the Knowledge Graph, with cycle-prevention for causal/DAG relations.

### Parameters
- `source` *(string, required)*: Source UUID or concept name.
- `target` *(string, required)*: Target UUID or concept name.
- `relation` *(string, required, enum: `"RELATED_TO"`, `"USED_IN"`, `"CAUSED_BY"`, `"SOLVES"`, `"CONTRADICTS"`, `"SUPERSEDES"`, `"DERIVED_FROM"`, `"DEPENDS_ON"`, `"PREFERS"`, `"AVOID"`)*: Canonical relationship type.
- `weight` *(number, optional, [0.0 - 1.0], default: 1.0)*: Edge weight.
- `context` *(string, optional)*: Explanatory rationale.

### Example
```json
{
  "source": "PostgreSQL-17",
  "target": "SQLite",
  "relation": "PREFERS",
  "weight": 0.95,
  "context": "Multi-agent concurrency and native pgvector extensions required for shared cognitive memory"
}
```

## 6. `brain_graph`
Traverses recursive multi-hop neighborhoods in the Knowledge Graph from a root node (1 to 5 hops).

### Parameters
- `node` *(string, required)*: Root memory UUID or concept label.
- `depth` *(integer, optional, 1 to 5, default: 1)*: Maximum traversal hop depth.
- `direction` *(string, optional, enum: `"outbound"`, `"inbound"`, `"both"`, default: `"both"`)*: Edge direction.
- `relation_types` *(array of strings, optional)*: Filter for specific relationship types.
- `min_weight` *(number, optional, [0.0 - 1.0])*: Minimum edge weight threshold.
- `limit` *(integer, optional, 1 to 100, default: 20)*: Maximum nodes to return.

---

## 7. `brain_learn`
Records an empirical observation or proposes a candidate belief in the continuous learning engine, updating confidence scores and attaching evidence sources.

### Parameters
- `statement` *(string, required)*: Factual observation or belief claim.
- `evidence` *(string, optional)*: Supporting or refuting empirical evidence.
- `source_type` *(string, optional, enum: `"human"`, `"tool_execution"`, `"direct_observation"`, `"agent_hypothesis"`, default: `"direct_observation"`)*: Origin of evidence.
- `domain` *(string, optional)*: Associated domain area or project.
- `agent` *(string, optional)*: Reporting agent identifier.
- `is_supporting` *(boolean, optional, default: true)*: `true` if evidence supports; `false` if it refutes/contradicts.
- `human_validated` *(boolean, optional, default: false)*: Marked as verified and approved by a human developer.
- `is_observation` *(boolean, optional, default: false)*: Recorded as a point-in-time observation without generalising to a belief.

---

## 8. `brain_explain`
Answers the core question: **"Why does the system believe this?"**, unpacking conclusion, accumulated evidence, consistency history, and formal confidence level.

### Parameters
- `query` *(string, required)*: Question, claim statement, or knowledge UUID to explain.
- `domain` *(string, optional)*: Optional domain filter.

---

## 9. `brain_consolidate`
Runs offline reflection and consolidation over recent experience clusters or specified memories, synthesizing candidate hypotheses and flagging contradictions.

### Parameters
- `project` *(string, optional)*: Filter by project.
- `memory_ids` *(array of strings, optional)*: Specific memory UUIDs to consolidate directly.
- `similarity_threshold` *(number, optional, [0.0 - 1.0], default: 0.82)*: Cosine similarity clustering threshold.
- `dry_run` *(boolean, optional, default: false)*: Simulate without persisting state changes.

---

## 10. `brain_forget`
Performs a safe logical soft-delete of an existing memory. Requires explicit confirmation to prevent accidental loss.

### Parameters
- `id` *(string, required)*: Memory UUID to delete.
- `confirm` *(boolean, required)*: Must be strictly `true`.

---

## 11. `brain_session_end`
Concludes an active working session, cleanly expiring and purging transient working memories (`working`).

### Parameters
- `session_id` *(string, required)*: Active session ID to terminate.
